# Публикация на GitHub: справочник

Публичность репозитория означает, что доступны **все его коммиты, ветки, теги, релизы и загруженные артефакты**, а не только текущий каталог файлов. `.gitignore` защищает от будущих случайных добавлений, но не удаляет сведения из Git-истории.

## Новый публичный репозиторий

Безопаснее создать **пустой** репозиторий и перенести в него только проверенные файлы публичной сборки, **без каталога `.git` от старого проекта**. Не используйте для публичного релиза историю репозитория, в котором ранее находились пароли, адреса серверов, идентификаторы пользователей или приватные конфигурации.

В директории с распакованными исходниками публичной сборки:

```bash
python3 scripts/check_secrets.py
for f in scripts/*.sh; do bash -n "$f"; done
(cd dist && sha256sum -c SHA256SUMS)
bash dist/vpn-manager-setup-0.5.2.sh --verify

git init -b main
git add .
git status --short
git diff --cached --stat
git diff --cached -- README.md docs/ deploy/bot.env.example
git commit -m "Initial public release"
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Замените `OWNER/REPOSITORY` адресом созданного репозитория. Перед `git commit` просмотрите **весь** индекс, включая код и встроенный установщик. Если в исходном архиве есть скрытые конфигурации или `.git`, исключите их ещё до `git add`.

## Что нельзя публиковать

Токены Telegram и API, файлы `bot.env`/`.env`, SQLite, архивы бэкапа, приватные SSH/TLS-ключи, доступные подписочные URL, данные пользователей, приватную IP-адресацию конкретной инфраструктуры. Не прикладывайте снимки экрана с учётными данными или настоящими ссылками.

При случайной утечке требуется **отозвать/сменить секреты**, после чего убрать его из истории публикации (новый коммит с удалением не делает секрет недоступным из старых коммитов). Автоматическая проверка не заменяет ручную проверку GitHub Actions, релизов и внешних артефактов.

## Поддержка релиза

При изменении исходников или документации пересобирайте `dist` через `python3 scripts/build_setup.py`, затем проверяйте SHA-256 и встроенный payload. В корне README сохраняйте пользовательскую структуру: краткое описание, требования, команды установки, типовые ошибки.
