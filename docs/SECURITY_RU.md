# Безопасность: эксплуатационные рекомендации

Этот проект предоставляет Telegram-боту административные возможности через API 3x-ui; компрометация токена панели может привести к изменению клиентских записей. Не следует рассматривать наличие локальных тестов как доказательство отсутствия уязвимостей.

- Работайте от отдельного системного пользователя `vpn-bot` с ограниченными правами, не от `root`. Сохраняйте ограничения `systemd` и ограничение записи в `/var/lib/vpn-bot`.
- Держите SSH на ключах, ограничивайте доступ к панели и используйте HTTPS с проверяемым сертификатом. Настройки межсетевого экрана и портов определяются фактическими требованиями сервера, а не универсальными номерами.
- Telegram Bot Token и 3x-ui API Token должны храниться только в защищённом `/etc/vpn-bot/bot.env` (типовой режим `640`, `root:vpn-bot`). Не передавайте их в командах, переписке, issue и логах.
- Не публикуйте реальные ссылки подписок, UUID, приватные ключи, `.env`, SQLite, файлы сертификатов и резервные копии. Добавьте защиту секретов в GitHub и проверяйте `git diff --cached` перед push.
- Не выдавайте административные права по имени `@username`: идентификатор администратора должен быть числовым Telegram ID; каждое действие должно проверять права на стороне бота.
- Подделка `callback_data`, повторные нажатия, спам и некорректные входные данные требуют валидации и ограничения частоты запросов; права и принадлежность тикетов нужно проверять для каждого действия.
- При `needs_review` не повторяйте операцию: сравните план с фактическим состоянием клиента через 3x-ui, затем оформите результат вручную. Используйте отдельные тестовые аккаунты для интеграционных проверок.
- После установки оставляйте `WRITE_ENABLED=false` до завершения проверок; TLS verification не отключайте на публичном сервере.
- Проводите аудит зависимостей и обновлений, тестируйте поведение при падении API, таймаутах и ответах неожиданных типов.

Команда `python3 scripts/check_secrets.py` предназначена для предварительной проверки **исходников и встроенного архива установщика**. Она не заменяет ручную проверку репозитория, Git-истории, артефактов CI и уязвимостей зависимостей.
